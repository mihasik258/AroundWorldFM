# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Напишите владельцу репозитория через GitHub (Security → Report a vulnerability). Ответ — в течение 7 дней.

## Что сделано

- Пароли: bcrypt (cost 12) поверх HMAC-SHA256 с секретным перцем; одинаковое время ответа для существующих и несуществующих логинов.
- Сессии: access JWT на 15 минут в памяти JS, refresh только в httpOnly/Secure/SameSite=Strict cookie, ротация с обнаружением повторного использования, мгновенный отзыв через `sid`.
- Telegram: проверка подписи `initData` за постоянное время и ограничение возраста; внутренний API бота закрыт секретом и nginx.
- SSRF: исходящие запросы к потокам только на публичные адреса, проверка на каждом редиректе.
- Заголовки: CSP, HSTS (Caddy), nosniff, Referrer-Policy, Permissions-Policy; ошибки без утечки внутренних данных.
- Лимиты частоты в nginx и приложении; контейнеры без root; зависимости закреплены, `pip-audit` и `npm audit` в CI, Dependabot.

## Известные ограничения

- Сборочные dev-зависимости Tailwind 3 содержат уязвимости класса DoS (в рантайм-бандл не попадают); устраняется переходом на Tailwind 4.
- Лимиты slowapi хранятся в памяти процесса; при нескольких воркерах основной барьер — nginx.
